## 目标
给生活一点颜色，让自己充满活力、有趣、鲜活和饱满。

生命力是生活实现自洽后的奖赏，不是系统获得运行资格的必修课。人除了工作，还应有滋养自己的热爱与活动；这里帮助认识和设计这些需要，而不是另加一套必须完成的健康、爱好建设任务。

---
## 内容范围

健康与爱好是理解生命力的两个角度，不是固定的内部模块。跑步既可能是爱好，也可能服务健康与社交，不必为它判定唯一类别，更不必据此拆出一套目录。

> [!multi-column] 
>
>> [!info]  爱好 ｜**我的边界**
>> 1️⃣ 认识让自己丰富多彩、愿意持续投入的热爱
>> 2️⃣ 研究如何融入已有生活，也可以与他人共同推进
>> 
> 
>> [!info]  健康 ｜**我的身心**
>>  1️⃣ 根据自身需要，设计适合自己的运动与活力改善内容
>>  2️⃣ 在实际使用中观察效果，按需要调整，不为指标而增加负担

## 与其他模块的关系

画像形成之后，并不意味着自我认识已经完成。认识到自己的状态与需要，还应按需要转化为设计、安排与实践，再通过反馈继续迭代。

| 位置 | 负责维护的内容 |
| :--- | :--- |
| [[画像]] | 自己当前的状态、特质、偏好，以及希望改善的地方 |
| 生命力 | 据此研究适合自己的运动、爱好等内容，形成滋养自己的设计 |
| [[蓝图]]、[[旅程]] | 将这些需要纳入整体生活策略与行动安排，协调时间、精力和资源 |
| [[第三课题]] | 与他人共同开展时，形成面向具体受众的邀请、活动与互动内容 |

分流依据是内容承担的职责，不是活动名称，也不是有没有步骤、指标或执行计划。各处通过引用保持关联，不重复维护同一份方案；实践反馈可以帮助更新画像、生命力设计和后续安排。

例如，“最近身体状态不好”先作为自我观察记录在画像中，原因需要辨明，不能直接认定为缺乏运动。确认需要通过运动改善后，在生命力中研究适合自己的内容，再纳入蓝图与旅程；与他人共同开展的部分，可以落实为具体项目中的活动。

## 融入生活，而非增加一套负担

面对一份难以割舍的热爱，优先研究如何让它与已有生活、业务和人际关系相互支持，而不是另建一套争抢时间与精力的安排。

例如，非常喜欢打羽毛球，可以结合自己的实际情况，设计与客户一起打球：生命力维护这份热爱及活动设计，第二课题统筹其与业务的关系和行动安排，第三课题组织面向客户的邀请与互动。既滋养自己，也让关系在真实活动中发展。

- 整合不是要求所有爱好都商业化，而是不让热爱与原有生活彼此割裂、相互消耗。
- 可以按实际需要记录和收集兴趣相关内容，但不为收集而收集、为维护而维护；是否值得投入，看它对自己是滋养还是消耗。
- 想法可以先按[[文件管理]]安放，需要使用时再研究和完善，不因记录了一项爱好，就自动增加计划、指标或待办。

---
> [!ai]- AI 协助
> - 不要求用户先建设生命力才能开展其他工作，不主动批量创建健康、爱好等子模块。
> - 结合用户确认的状态、需要与现实条件，协助形成安全、适合本人的设计，并研究如何融入已有生活；不把所有结构化方案自动归入生命力，也不默认所有爱好都要转成业务。
> - 区分自我观察、原因假设与已确认事实；不根据一句身体不适就自行诊断或认定原因，不提供医学视角的建议和帮助，需要专业判断时说明边界。
> - 按职责连接画像、生命力、第二课题与第三课题，不把内部状态原样写成对外内容。写入或调整其他模块前，确认用户的意图与授权，不以完善系统为由自动安排任务。
