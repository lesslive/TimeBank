# Lesslive 社区建设指南

> 依据 GitHub 原生能力构建、由一人公司（One-Person Company）实践者共建的生活圈小镇。
> 本文档作为创建与运营 Lesslive 社区的正式依据与操作指南。

---

## 一、底层逻辑

**主张：** AI 时代，普通人的出路之一是借助 GitHub 链接全球。

两条底层逻辑：
1. **链接全球** —— 接入无边界的实践者网络。
2. **AI 全支持** —— AI 具备对 GitHub 平台整套操作的能力。

**关键边界：**
- AI 负责的是**维护 GitHub 仓库的操作层**：clone、fork、提交、文档格式化、站点维护、提交流程、消息汇总。
- AI **不负责你的内容创作、产品与服务**。这些仍由人主导。

**SSOT 单一事实来源原则：**
定稿资产由 Git 文件承载，所有社区交流收敛到统一讨论区，避免信息碎片化。

---

## 二、社区模型

Lesslive 是一座虚拟小镇，GitHub 原生能力就是小镇的基础设施，无需自建系统。

| 角色                 | 对应 GitHub 实体             | 说明                            |
| ------------------ | ------------------------ | ----------------------------- |
| 小镇地址               | 组织 `lesslive`            | 统一命名空间 `github.com/lesslive/` |
| Lesslive 组织成员使用的方法 | 仓库 `opc.os`              | 给用户的方法论和架构                    |
| 官网数据源              | 仓库 `.github`             | 组织主页和官网静态定稿数据源仓库              |
| 成员宅基地              | 成员仓库 `<user-reops-name>` | 成员在 lesslive 组织内创建的仓库，用来展示自己  |
| 邻里关照               | Watch / 订阅通知             | 成员间互相关注仓库、感知更新                |

---

## 三、社区分层

| 层级   | 准入门槛             | 能力与权益                                    |
| ---- | ---------------- | ---------------------------------------- |
| 访客   | 拥有 GitHub 账号即可   | 浏览全部公开仓库、浏览组织 Discussions；不能创建仓库、可以发帖和评论 |
| 组织成员 | 申请加入 lesslive 组织 | 可在组织下创建公开仓库，管理自己的仓库                      |

**组织成员的两类自主选择：**
- 创建仓库，在小镇拥有一块公开展位；
- 不建仓库，只参与公共仓库的讨论与共建。

**公开资料与付费服务：**
- 公开仓库、OPC.OS 资料：任何人免费浏览、Fork、下载。
- 付费专属服务：线下课、定制资料、陪跑等，独立于 GitHub 权限体系另行交付，不影响免费基础设施的使用。

---

## 四、成员价值与权益

- **身份背书**：店铺地址位于 `github.com/lesslive/` 命名空间下，获得共同体背书。
- **展示橱窗**：成员仓库即个人空间，面向全部访客公开浏览。
- **独立站点**：仓库自带 GitHub Pages，可生成网站，可绑定独立域名。
- **内容自主**：成员仓库内原创内容著作权归创作者本人。
- **永久展位**：成员仓库一旦创建，即成为 lesslive 的长期展位，持续为成员引流曝光。

---

## 五、交互规则

整个社区**只有一处交流阵地**：组织 Discussions（底层依托 `lesslive/opc.os`）。

- `opc.os`：开启 Discussions；关闭 PR、Issues、Wiki。
- `.github` 等官方公共仓库：全部关闭 Pull Requests、Issues、Wiki、仓库级 Discussions，仅作为只读静态资产。

**邻里关照与  AI 协助：**
- 店铺互访：成员在帖中附上自己店铺链接，互相访问、链接。
- 订阅跟进：Watch 他人店铺仓库，开启通知，感知更新动态。
- AI 协助：组织成员自己的本地 Agent（如 Codex）替成员盯留言、跟更新、汇总推送，无需频繁登录 GitHub。

---

## 六、权限设计

### 成员权限
- **Base permissions = Read**：所有组织成员对他人已创建的仓库仅拥有只读权限。
- **Repository creation**：仅 Public（允许成员创建公开仓库）；

### 仓库权限
- **谁创建，谁管理**：成员新建仓库后，自动成为该仓库的 Maintainer，全权维护该仓库（写内容、开 Pages、管理 PR 和分支、添加协作者、维护提问和讨论、删除和转让等）。
- **不能修改他人仓库**：非本人创建的仓库一律只读，只能浏览、提 PR。
### 分支保护
- OPC.OS 仓库 `main` 分支：禁止强制推送、禁止分支删除、禁止绕过保护规则。

## 七、组织仓库

```
lesslive/
├── opc.os          # lesslive 总库 + 唯一讨论广场
├── .github         # 官网数据源，纯静态定稿
├── <user-reops-name>      # 成员仓库
└── 其他公共协作仓库   # 按需创建
```

**OPC.OS 三课题：**
1. 第一课题：初心动念（愿景、使命、主张）
2. 第二课题：谋生手段（平台、渠道、资源）
3. 第三课题：个人项目（产品、内容、服务）

---
> 星云可视化：将成员在 lesslive 的行为数据渲染成星云，放于 lesslive.com。不搞排行榜，只客观呈现谁与谁产生了连接、谁在持续生长。
